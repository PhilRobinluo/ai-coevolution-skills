# 罗老师文章截图助手

> 类型：LLS Original  
> 当前版本：1.0.0

## 一句话用途

为教程建议截图位置，并在 macOS 上生成命名清楚的项目截图。

## 什么时候使用

写软件教程、操作说明或产品复盘，需要真实界面证据。

## 哪些情况换别的方法

页面包含大量隐私且尚未准备脱敏。

## 3 分钟上手

复制下面这句话给 AI：

```text
请用 lls-article-screenshot，给这篇安装教程补三张关键截图。
```

## 标准工作流程

1. **确定截图要证明什么**
2. **选择区域、窗口、全屏或延时模式**
3. **保存到项目assets目录并生成Markdown引用**
4. **调用隐私打码流程后再公开**

## 完整案例

输入：CLI安装教程。

输出：建议截“版本号、登录成功、发布回执”三处，并生成图片引用。

## 输出标准

最终结果至少包含：

- 用户真正要完成的任务；
- 可执行步骤，而不是只有观点；
- 关键事实、假设和未知项；
- 完成前的检查清单；
- 下一步最小动作。

## 隐私、依赖与权限

全屏截图风险最高；优先截最小区域并关闭通知和无关窗口。

默认只读取用户明确提供的材料。涉及账号登录、文件写入、网络请求或外部发布时，先说明实际动作与影响范围。

## 质量检查

交付前逐项检查：

1. 是否回答了用户的真实任务；
2. 是否把事实、推断和建议分开；
3. 是否给出至少一个可复制的下一步；
4. 是否移除了本机路径、账号、密钥和客户资料；
5. 是否说明依赖、权限和失败处理。

## 常见问题

### 结果太泛怎么办？

补充目标用户、真实输入、期望输出和一个失败例子，再运行一次。

### 可以直接公开结果吗？

先检查来源、个人信息、客户内容、截图和下载链接，再决定发布范围。
