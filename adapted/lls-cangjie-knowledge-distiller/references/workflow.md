# WorkBuddy 知识蒸馏流程

## 目录

1. 输入合同
2. 全局理解
3. 候选筛选
4. Skill 制作
5. 交付边界

## 1. 输入合同

先记录材料的标题、作者或讲者、发布日期、文件位置和用户希望解决的问题。公开发布时只记录可公开的来源链接或书目信息，不把完整受限材料打进安装包。

## 2. 全局理解

`CONTENT_OVERVIEW.md` 至少回答：

- 这份材料试图解决什么问题？
- 内容由哪几个部分组成？
- 作者反复使用哪些术语？
- 作者依赖哪些没有明说的假设？
- 哪些方法可以跨场景迁移？
- 哪些结论只适用于特定时代、行业或样本？

长材料按章节、讲次或时间段分块。每块写一张结构卡，最后合并；不要用首尾几段代表全文。

## 3. 候选筛选

为每个候选方法建立记录：

```text
候选名称：
类型：框架 / 原则 / 案例模式 / 反例模式
证据位置：
第二处独立证据：
可预测的新问题：
区别于常识：
边界：
结论：保留 / 淘汰 / 待补证据
```

证据不足时放进“待补证据”，而不是为了凑数量进入 Skill 制作。

## 4. Skill 制作

一个 Skill 只承担一种稳定能力。若两个候选的触发情境、执行步骤和失败边界明显不同，应拆开；若它们总是同时出现且独立后没有价值，应合并。

最终 `description` 应让 WorkBuddy 只看这一段就能区分：

- 用户出现什么任务信号时调用；
- 调用后要产生什么结果；
- 哪些相似任务属于兄弟 Skill 或普通摘要。

## 5. 交付边界

构建产物与安装产物分开：

- 构建区保留候选、淘汰记录、长摘要和测试结果；
- 安装区只放独立 Skill 工作所需的 `SKILL.md`、references、scripts 和 assets；
- 公开包不包含原书、完整字幕、客户文档和本机路径；
- 发布前重新检查来源权利、隐私、版本与目标平台状态。
