# WorkBuddy 错误诊断树

## 诊断顺序

先问：“最终成品是什么，当前实际得到什么？”然后从上到下只检查一个最可能缺口。

| 类别 | 常见表现 | 核验问题 | 最小修复 |
|---|---|---|---|
| 目标 | 一直答非所问、结果很泛 | 成品、读者、用途和完成标准写清了吗 | 重写任务卡，只保留一个成品 |
| 资料 | 内容空、事实少、风格不对 | 是否给了必要资料和参考样例 | 补最小资料片段或合成样例 |
| 能力 | 模式、Skill 或工具选错 | 任务是否重复、是否访问外部系统 | 重新按路由表选择一次 |
| 执行 | 任务太大、卡在中间 | 是否有可检查的中间产物 | 拆成一个 5 分钟步骤 |
| 验收 | 只看到“完成”提示 | 成品是否能打开，事实和格式是否核对 | 执行适用的四证验收 |
| 权限 | 外部工具没有变化 | 是否登录、授权、选对账号和对象 | 先只读验证，再展示写入计划 |

## 定向恢复话术

### 目标缺口

```text
我们先把任务缩成一个成品。
请补全：给谁用、输出什么、怎样算完成。
```

### 资料缺口

```text
当前缺少支撑结果的资料。
请只补最必要的一段文字、一个文件或一个公开链接。
```

### 能力选择缺口

```text
这一步需要重新选能力：
重复流程看 Skill，外部系统看连接器，专业判断看专家，
最后再选 Ask / Plan / Craft。
```

### 执行缺口

```text
先只完成一个可检查的小步骤，产出中间结果后再继续。
```

### 验收缺口

```text
现在不继续加工，先检查成品、事实、格式和外部读回。
```

### 权限缺口

```text
先确认真实账号、目标对象和只读访问结果，
再展示准备写入的内容和影响范围。
```

## 复测规则

- 修正一个缺口后立刻重复原验收。
- 新证据出现后再判断下一项。
- 连续两次失败时进一步缩小任务。
- 将卡点摘要写入学习档案，用于下一次教学。
