# 罗老师同事经验蒸馏器

> 类型：LLS Adapted
> 当前版本：1.0.0
## 一句话用途

把“这个人平时是怎么把工作做好”的隐性经验，整理成新人或 Agent 能重复执行、能检查结果的岗位 Skill。

## 默认选择

默认蒸馏**岗位方法**，不制作完整人格复制。对象可以是同事、导师、合作伙伴，也可以直接是一类岗位。内部资料生成的结果默认留在私有工作区。

## 适合的任务

- 离职或轮岗前的岗位交接；
- 提取老员工的检查清单与判断标准；
- 把聊天、评审意见和复盘整理成流程；
- 生成岗位 Skill 的第一版蓝图；
- 用后续纠正记录持续更新已有 Skill。

## 3 分钟上手

```text
请使用 lls-colleague-skill-distiller，把“产品经理每周整理客户反馈”的方法蒸馏成岗位 Skill。先列资料清单和隐私边界，再生成不含任何真实客户信息的蓝图。
```

## 六阶段流程

### 1. 确认范围与资料权利

记录：

- 蒸馏对象或岗位；
- 允许使用的资料；
- 使用目的和可见范围；
- 哪些信息必须删除或替换；
- 是否获得对象或资料管理者的同意。

范围不清时，先做岗位模板，不读取私人聊天或个人账户。

### 2. 建立工作地图

用下面六格描述岗位：

```text
职责范围：负责什么，不负责什么
触发场景：什么时候开始工作
输入材料：需要哪些信息
执行流程：通常按什么顺序
判断标准：如何取舍、何时升级
交付结果：格式、质量和时限
```

### 3. 收集最小证据集

优先收集：

1. 已脱敏的代表性产出；
2. 标准流程、检查表和模板；
3. 评审意见与返工原因；
4. 常见异常及处理方式；
5. 对同一任务的多个真实案例。

聊天记录只提取与工作直接相关的判断，不保留闲聊、身份信息和关系内容。详细边界见 `references/privacy-boundary.md`。

### 4. 提炼能力层

把资料转成四类可执行资产：

- **流程**：从输入到交付的步骤；
- **判断**：遇到分叉时依据什么选择；
- **质量门禁**：怎样判断完成；
- **失败处理**：缺资料、冲突、超时或风险出现时怎么做。

表达风格作为可选层，只有与工作效果直接相关且来源明确时才加入。

### 5. 生成岗位 Skill

生成内容至少包括：

- 触发词与适用任务；
- 输入清单和默认值；
- 主流程与失败分支；
- 模板、检查表和输出示例；
- 公开边界与内部边界；
- 三个合成测试任务。

生成模板见 `references/role-skill-template.md`。

### 6. 试岗与纠正

使用合成数据执行：

1. 一次正常任务；
2. 一次缺少关键信息的任务；
3. 一次容易暴露内部信息的任务。

记录“哪里不像真实工作”“遗漏了哪条判断”“哪些步骤多余”。纠正记录只改变有证据支持的规则，并保留版本说明。

## 私有版与公开版

```text
内部资料库 → 私有岗位 Skill → 团队试岗
                         ↓ 人工脱敏与重写
公开资料与合成案例 → 独立公开版 Skill → 公开仓库
```

公开版从合成案例重新编写，不从内部目录直接复制，也不自动同步。

## 不要这样做

- 直接上传整段私人聊天或邮箱；
- 把人格、关系和工作能力混成一个公开包；
- 把真实客户、公司、项目和系统地址写进示例；
- 用某个人的名字掩盖岗位范围不清；
- 将内部生成结果直接发布到 GitHub、飞书或 SkillHub；
- 把一次成功经验写成永远适用的规则。

## 完成检查

- [ ] 范围、用途和资料权利已记录；
- [ ] 岗位地图六格完整；
- [ ] 示例和测试均已脱敏或使用合成数据；
- [ ] 流程、判断、质量与失败处理均可执行；
- [ ] 私有版和公开版位于独立目录；
- [ ] 公开版未包含姓名、账号、客户、内部链接或凭证；
- [ ] 已用三类测试完成试岗。
