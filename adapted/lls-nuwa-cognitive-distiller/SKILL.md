# 罗老师女娲认知蒸馏器

> 类型：LLS Adapted
> 当前版本：1.0.0
## 一句话用途

把散落在书籍、访谈、演讲和公开决策中的思考方法，整理成可调用、可验证、会说明局限的认知 Skill。

## 适合的任务

- 蒸馏公开人物、作者、行业高手或公开主题；
- 研究某人如何拆问题、排序、取舍和表达；
- 给已有的人物 Skill 补充证据、反模式与诚实边界；
- 比较两位人物面对同一问题时的不同判断框架。

## 默认输出

创建一个独立 Skill 蓝图，至少包含：

1. 适用问题与触发条件；
2. 3—7 个心智模型；
3. 5—10 条决策启发式；
4. 表达特征与代表性结构；
5. 明确的反模式；
6. 诚实边界与未知项；
7. 已知问题、迁移问题和失败用例。

## 3 分钟上手

```text
请使用 lls-nuwa-cognitive-distiller，基于公开资料蒸馏“费曼如何解释复杂知识”。先给调研计划和来源标准，再生成 Skill 蓝图，不要把推断写成原话。
```

## 标准流程

### 1. 定义对象与用途

先写清：

- 对象是谁或主题是什么；
- 用户希望解决哪类问题；
- 需要全面画像还是单一维度；
- 结果用于个人研究、团队参考还是公开发布。

同名人物或歧义主题先消歧。没有明确用途时，默认制作“公开认知顾问”，而不是模仿秀。

### 2. 建立公开来源矩阵

至少覆盖三类材料，优先级如下：

1. 本人的著作、演讲、访谈与官方文章；
2. 可核验的决策记录、项目复盘与长期行为；
3. 批评者、合作者和不同立场的分析。

每条重要结论记录来源链接、日期、原始语境和证据类型。来源选择细则见 `references/extraction-checklist.md`。

### 3. 分开记录事实、解释与推断

为每个候选模型建立证据卡：

```text
模型名称：
公开证据：
跨场景重复：
可预测的新问题：
区别于常识的地方：
反例或冲突证据：
结论类型：事实 / 解释 / 推断
```

一个观点只有在多个独立场景中重复出现、能解释真实选择并对新问题有预测力时，才进入核心模型。

### 4. 提炼五层认知结构

按以下五层组织：

- **心智模型**：他用什么框架看问题；
- **决策启发式**：信息不完整时如何快速判断；
- **表达结构**：如何组织论证，不只记录口头禅；
- **反模式**：哪些做法会被拒绝，为什么；
- **诚实边界**：公开资料覆盖到哪里，哪些仍属推断。

### 5. 生成 Skill

生成的 `SKILL.md` 应包含触发条件、回答流程、证据约束、模型调用方式、反例、边界和测试。人物名称与生成器名称分开，避免目录冲突。

### 6. 三组验证

- **已知问题**：选择三道本人公开回答过的问题，检查方向是否一致；
- **迁移问题**：选择一道本人未公开回答的新问题，检查框架能否迁移；
- **诚实测试**：证据不足时，输出应标记推断和未知，而不是制造确定口吻。

验证未通过时，回到证据卡或删掉不稳定模型，不靠增加人物口头禅掩盖问题。

## 输出格式

```markdown
# 蒸馏报告

## 对象与用途
## 来源矩阵
## 核心心智模型
## 决策启发式
## 表达结构
## 反模式
## 诚实边界
## Skill 蓝图
## 测试题与结果
## 待补证据
```

## 隐私、来源与边界

- 公开人物路线只使用可核验公开材料；
- 用户提供的书摘、聊天或内部文档默认保留在当前工作区；
- 引文保留出处，长内容用概括替代复制；
- 输出使用“依据公开资料推断”，不冒充本人私下观点；
- 涉及健康、法律、投资等专业决策时，把人物框架与专业意见分开。

## 不要这样做

- 只收集名言和口头禅；
- 用单篇文章概括一个人的全部思想；
- 把粉丝解读写成本人结论；
- 为了像本人而制造未经证实的经历或原话；
- 把公开人物研究与内部同事资料放进同一发布包。

## 完成检查

- [ ] 对象和用途已经消歧；
- [ ] 核心模型有跨来源证据；
- [ ] 事实、解释和推断已分开；
- [ ] 包含反例与诚实边界；
- [ ] 三组测试均有记录；
- [ ] 公开产物未包含私人材料、账号或内部链接。
